# 판다스 이론 MD 작성 가이드 (작성 전 필독)

> 모든 이론 문서는 이 가이드를 기준으로 작성한다. 새 문서를 쓰기 전 반드시 본 파일과 `_검수체크리스트.md`를 먼저 읽는다.
> 기준 샘플: `01_Series와_DataFrame.md` (이 분량·깊이·톤을 표준으로 삼는다).

---

## 1. 대상과 톤

- **대상**: 완전 초보자 (파이썬 기초 문법만 끝낸 사람). NumPy·통계 지식 가정하지 않음.
- **톤**: 친절한 설명체. 어려운 용어는 처음 등장 시 **반드시 풀어서** 설명하고 비유(주로 엑셀)를 곁들인다.
- **문체**: "~함/~임" 또는 "~합니다" 중 하나로 일관. 샘플은 설명은 경어(~합니다), 요약/정의는 간결체 혼용 → 이 톤 유지.
- **영어 용어**: 한글(영어) 병기. 예) 결측치(missing value), 인덱스(index).

## 2. 분량 기준 (중요)

기준 샘플 `01_Series와_DataFrame.md` 수준을 **하한선**으로 한다.

- 전체: **약 280~360줄**, 본문 섹션 **8개 내외** (들어가며 ~ 핵심요약 + 다음파트).
- 다루는 함수/메소드가 많은 파트(예: 전처리)는 더 길어도 됨. **짧게 줄이지 말 것.**
- 함수·메소드 **하나당 평균 15~30줄** 분량으로 충실히.

## 3. 필수 구조 (섹션 순서)

```
# Part N · 제목 — 한 줄 부제
> 학습 목표 (3개 내외) + 선행 지식
---
## 0. 들어가며  — 왜 이 주제인가 (개념 큰그림 + 엑셀/실생활 비유 + 분석 프로세스상 위치)
## 1~K. 주제별 본문   — 함수·메소드별 7요소(아래) 충실히
## (분석) 데이터 분석 프로세스에서의 활용  — 실무 한 사이클 코드 예시
## 자주 하는 실수 체크리스트  — [ ] 형식 5~8개
## 핵심 요약  — 번호 목록 + 미니 퀴즈 2~3개(정답 포함)
> 다음 파트 → 안내(한 단락)
```

## 4. 함수·메소드 7대 필수 요소 (모든 함수/메소드에 적용)

각 함수/메소드를 소개할 때 아래 7가지를 **빠짐없이** 포함한다.

1. **개념** — 무엇을 하는가 (한두 문장)
2. **원리** — 왜/어떻게 동작하는가 (초보가 오해하기 쉬운 내부 동작)
3. **함수명/메소드명** — 정확한 이름 (`pd.read_csv`, `.groupby` 등)
4. **인수 구성** — 표로: `| 인수 | 의미 | 기본값 |` (자주 쓰는 인수 위주, 기본값 명시)
5. **문법** — 시그니처를 ```python 코드블록으로
6. **사용법** — 실제 예제 코드 + **예상 출력**(주석이나 출력 블록)
7. **데이터 분석 활용** — 실무에서 언제/왜 쓰는지 (📊 콜아웃)

## 5. 서식 규칙

- **인수/비교는 표(markdown table)** 로 정리. (인수표, iloc vs loc 같은 비교표)
- **코드블록**은 ```python. 출력은 코드블록 아래에 ``` 블록 또는 `# 주석`으로.
- **콜아웃 이모지** 일관 사용:
  - 💡 팁 / 알아두면 좋은 것
  - ⚠️ 흔한 실수 · 주의
  - 📊 데이터 분석 관점
  - ✅ 권장 / 올바른 사용
- 굵게(`**`)는 핵심 용어·강조에만. 남발 금지.
- 표·콜아웃·코드 앞뒤로 빈 줄 (렌더링 안정).

## 6. 예제 데이터 도메인

- 강의 노트북의 **실제 예제·도메인을 우선** 사용 (매출·주식종목·멤버십·렌탈·커머스 배송 등).
- 노트북에 없으면 같은 도메인(상품/매출/회원)으로 자연스럽게 만들되, **현실적인 값** 사용.
- 파트 간 도메인이 들쭉날쭉하지 않게, 가능하면 멤버십·커머스 맥락으로 연결.

## 7. 정확성 원칙

- 함수 시그니처·인수 기본값·반환형은 **실제 pandas 동작과 일치**해야 한다.
- 예상 출력은 **추측하지 말고**, 검수 단계에서 샌드박스 실행으로 확인한 값을 쓴다.
- 버전에 따라 달라지는 동작(예: `append` 제거, `df.mad()` 등)은 최신(2.x) 기준으로.
