모듈 · 패키지 · 라이브러리
남의 코드를 가져다 쓰는 법

지금까지는 코드를 직접 짰음. 하지만 실무에서는 이미 잘 만들어진 코드를 가져다 씀. import 한 줄이면 수학·날짜 함수는 물론, 곧 배울 판다스까지 내 것처럼 쓸 수 있음. 그 "가져다 쓰는" 단위가 모듈·패키지·라이브러리임.

🧩 선행 학습 import · pip · PyPI 예상 25분
01

왜 나누는가 — 코드 재사용

모든 코드를 한 파일에 짜면 길어지고, 같은 코드를 매번 다시 짜게 됨. 자주 쓰는 기능은 파일로 따로 빼두고(모듈), 필요할 때 불러(import) 재사용함.

예를 들어 원의 넓이를 구할 때 매번 3.14159...를 직접 적는 대신, 누군가 만들어 둔 math 모듈의 math.pi를 가져다 쓰면 됨.

📌 핵심  "직접 만들기"보다 "검증된 코드를 가져다 쓰기"가 빠르고 안전함. 그 결과 ① 중복이 사라지고 ② 유지보수가 쉬워지고 ③ 협업(각자 만든 걸 합치기)이 됨.
3줄 요약
  1. 자주 쓰는 코드는 파일로 빼서 재사용함.
  2. 가져다 쓰면 중복 제거·유지보수·협업에 유리.
  3. 가져오는 단위가 모듈 → 패키지 → 라이브러리.
02

모듈(Module) — .py 파일 하나

모듈은 함수·변수·클래스를 담아 둔 파이썬 파일(.py) 하나임. import로 불러오는 방법은 네 가지가 있음. 버튼을 눌러 코드와 사용법이 어떻게 달라지는지 보세요.

인터랙티브 · import 4가지 방법

표준 라이브러리 — 설치 없이 바로 쓰는 모듈

파이썬을 깔면 기본으로 따라오는 모듈 묶음임.

import math      # math.pi, math.sqrt(16) → 4.0
import random    # random.randint(1, 6)
import datetime  # datetime.date.today()
📌 참고  내가 만든 .py 파일도 모듈임. my_utils.py를 만들면 import my_utils로 불러 쓸 수 있음. 관례적으로 import numpy as np, import pandas as pd처럼 별명을 붙임.
3줄 요약
  1. 모듈 = 함수·클래스를 담은 .py 파일 하나.
  2. import·from~import·as로 불러 씀.
  3. math·random·datetime은 설치 없이 쓰는 표준 라이브러리.
03

패키지(Package) — 모듈을 담은 폴더

패키지는 여러 모듈을 폴더로 묶은 것임. 관련된 모듈을 주제별로 정리한 서랍장이죠. 트리에서 각 항목을 눌러 무엇인지 확인해 보세요.

인터랙티브 · 패키지 폴더 구조
📁 my_package/ # 패키지(폴더)
  ├── __init__.py # 패키지 표시
  ├── math_tools.py # 모듈
  └── string_tools.py # 모듈

점(.)으로 경로를 따라 접근함.

from my_package import math_tools
from my_package.string_tools import clean_text
📌 판다스로 직결  판다스도 거대한 패키지임. from pandas.api.types import is_numeric_dtype처럼 점으로 내부 모듈에 접근함.
3줄 요약
  1. 패키지 = 모듈을 담은 폴더.
  2. __init__.py가 있으면 패키지로 인식(관례).
  3. 점(.)으로 패키지 안 모듈·함수에 접근.
04

라이브러리 · 프레임워크 — 용어 정리

크기와 역할에 따라 부르는 이름이 다름. 버튼을 눌러 각 용어의 위치와 뜻을 확인해 보세요. 포함관계는 모듈 ⊂ 패키지 ⊂ 라이브러리임.

인터랙티브 · 포함관계
📚 라이브러리 (도서관)
🗄️ 패키지 (책장 칸)
module_a.py module_b.py
용어뜻비유
모듈.py 파일 하나책 한 권
패키지모듈을 담은 폴더책장 한 칸
라이브러리특정 목적의 코드 묶음도서관
프레임워크뼈대를 제공, 내가 채움건물 골조
📌 라이브러리 vs 프레임워크  라이브러리는 내가 불러서 쓰고(주도권: 나), 프레임워크는 틀이 내 코드를 불러 돌림(주도권: 틀). "라이브러리는 내가 부른다, 프레임워크는 나를 부름." 우리가 배울 NumPy·pandas·matplotlib는 모두 라이브러리임.
3줄 요약
  1. 모듈 ⊂ 패키지 ⊂ 라이브러리(규모가 커지는 순).
  2. 라이브러리는 내가 불러 쓰고, 프레임워크는 내 코드를 불러 돌림.
  3. NumPy·pandas는 라이브러리.
05

pip 와 PyPI — 외부 라이브러리 설치

표준 라이브러리에 없는 것은 외부 저장소에서 설치해서 씀. PyPI는 전 세계 개발자가 올린 파이썬 패키지 창고(파이썬 앱스토어)이고, pip은 거기서 내려받아 설치하는 도구임.

pip install pandas          # 설치
pip install pandas==2.2.0   # 특정 버전
pip install --upgrade pandas# 업그레이드
pip list                    # 설치된 목록
pip uninstall pandas        # 삭제
⚠️ 설치 ≠ 사용  설치(pip install)로 패키지를 컴퓨터에 내려받고, 코드에서는 import로 불러옴. 둘은 다른 단계임. pip install pandas로 깐 뒤 import pandas as pd로 사용함.
📌 참고  아나콘다를 쓰면 conda install로도 설치할 수 있음(다음 강의). 한 환경에서 pip·conda를 섞으면 충돌이 생길 수 있어, 한 방식으로 통일하는 것이 좋음.
3줄 요약
  1. PyPI = 파이썬 패키지 창고, pip = 설치 도구.
  2. pip install 패키지로 설치, import로 사용(다른 단계).
  3. 판다스도 설치해서 쓰는 외부 라이브러리.
06

마무리 — 판다스도 라이브러리임

정리하면 모듈(파일) → 패키지(폴더) → 라이브러리(묶음) 순으로 커지고, import로 가져오며, 없으면 pip install로 설치함. 판다스도 하나의 라이브러리일 뿐임.

그런데 라이브러리가 많아지면 서로 요구하는 버전이 충돌함. 이를 깔끔하게 관리하는 도구가 다음 강의의 아나콘다와 가상환경임.
