## 0. 들어가며 (히어로)
- 부제: "남의 코드를 가져다 쓰는 법"
- 리드: 지금까지는 내가 직접 코드를 짰습니다. 하지만 실무에서는 **이미 잘 만들어진 코드를 가져다 씁니다.** `import` 한 줄이면 수학 함수, 날짜 계산, 그리고 곧 배울 **판다스**까지 내 것처럼 쓸 수 있습니다. 그 "가져다 쓰는" 단위가 모듈·패키지·라이브러리입니다.

## 1. 왜 나누는가 — 코드 재사용
**핵심 메시지:** 모든 코드를 한 파일에 짜면 길어지고, 같은 코드를 매번 다시 짜게 된다.

- 예: 원의 넓이를 구하려면 매번 `3.14159...`를 직접 적어야 할까? 누군가 만든 `math` 모듈의 `math.pi`를 쓰면 된다.
- 자주 쓰는 기능은 **파일로 따로 빼두고(모듈), 필요할 때 불러(import)** 재사용한다.
- 장점: ① 중복 제거 ② 유지보수 쉬움 ③ 협업(각자 만든 걸 합침).

> 📌 핵심: "직접 만들기 vs 가져다 쓰기" — 검증된 코드를 가져다 쓰면 빠르고 안전하다.

---

## 2. 모듈(Module) — `.py` 파일 하나
**정의:** 모듈은 **함수·변수·클래스를 담아 둔 파이썬 파일(`.py`) 하나**다.

### 불러오는 4가지 방법 (인터랙티브 위젯 대상)
```python
import math                 # ① 모듈 전체 → math.sqrt(16)
from math import sqrt       # ② 특정 함수만 → sqrt(16)
from math import sqrt, pi   # ③ 여러 개
import math as m            # ④ 별명(as) → m.sqrt(16)
from math import *          # (비권장) 전부 가져오기 — 이름 충돌 위험
```
- `import 모듈` → 쓸 때 `모듈.함수()`로 (어디서 왔는지 명확).
- `from 모듈 import 함수` → 함수명만으로 바로 사용.
- `as` → 긴 이름에 짧은 별명. (관례: `import numpy as np`, `import pandas as pd`)

### 표준 라이브러리 — 설치 없이 바로 쓰는 모듈들
파이썬을 깔면 **기본으로 따라오는** 모듈 묶음.
```python
import math      # math.pi, math.sqrt(), math.ceil()
import random    # random.randint(1, 6), random.choice([...])
import datetime  # datetime.date.today()
```
> 📌 참고: 내가 만든 `.py` 파일도 모듈이다. `my_utils.py`를 만들면 `import my_utils`로 불러 쓸 수 있다.

**3줄 요약**
1. 모듈 = 함수·클래스를 담은 `.py` 파일 하나.
2. `import`·`from~import`·`as`로 불러 쓴다.
3. math·random·datetime은 설치 없이 쓰는 표준 라이브러리.

## 3. 패키지(Package) — 모듈을 담은 폴더
**정의:** 패키지는 **여러 모듈을 폴더로 묶은 것**이다. 관련된 모듈들을 주제별로 정리한 서랍장.

### 구조 (시각화 대상 — 폴더 트리)
```
my_package/            ← 패키지(폴더)
├── __init__.py        ← "이 폴더는 패키지" 표시(있으면 패키지로 인식)
├── math_tools.py      ← 모듈
└── string_tools.py    ← 모듈
```
- 점(`.`)으로 경로를 따라 접근:
```python
from my_package import math_tools
from my_package.string_tools import clean_text
```
- 패키지 안에 또 패키지(하위 패키지)를 둘 수도 있다 → 계층 구조.

> 📌 판다스도 거대한 패키지다. `from pandas.api.types import is_numeric_dtype`처럼 점으로 내부 모듈에 접근한다.

**3줄 요약**
1. 패키지 = 모듈을 담은 폴더.
2. `__init__.py`가 있으면 패키지로 인식(최신 파이썬은 없어도 동작하나 관례상 둠).
3. 점(`.`)으로 패키지 안 모듈·함수에 접근.

## 4. 라이브러리 · 프레임워크 — 용어 정리
**핵심:** 크기·역할에 따라 부르는 이름이 다르다. (포함관계 다이어그램 대상)

| 용어 | 뜻 | 비유 |
|---|---|---|
| **모듈** | `.py` 파일 하나 | 책 한 권 |
| **패키지** | 모듈을 담은 폴더 | 책장 한 칸 |
| **라이브러리** | 특정 목적의 코드 묶음(여러 패키지·모듈) | 도서관 |
| **프레임워크** | 뼈대를 제공하고 내가 그 안을 채움 | 건물 골조 |

- 포함관계: **모듈 ⊂ 패키지 ⊂ 라이브러리**. (엄밀한 경계는 느슨하며, 흔히 섞어 부른다)
- **라이브러리 vs 프레임워크의 차이(중요):**
  - 라이브러리 = **내가** 필요할 때 **불러서** 쓴다 (주도권: 나). 예: NumPy, pandas, requests.
  - 프레임워크 = **틀이** 내 코드를 불러서 돌린다 (주도권: 프레임워크). 예: Django, Flask.
  - "라이브러리는 내가 부른다, 프레임워크는 나를 부른다."

> 📌 그래서 우리가 배울 **NumPy·pandas·matplotlib는 모두 "라이브러리"**다.

**3줄 요약**
1. 모듈 ⊂ 패키지 ⊂ 라이브러리(규모가 커지는 순).
2. 라이브러리는 내가 불러 쓰고, 프레임워크는 내 코드를 불러 돌린다.
3. NumPy·pandas는 라이브러리.

## 5. pip 와 PyPI — 외부 라이브러리 설치
**핵심:** 표준 라이브러리에 없는 것은 **외부 저장소에서 설치**해서 쓴다.

- **PyPI** (Python Package Index): 전 세계 개발자가 올린 파이썬 패키지 창고(파이썬 앱스토어).
- **pip**: PyPI에서 패키지를 내려받아 설치하는 도구.
```bash
pip install pandas          # 설치
pip install pandas==2.2.0   # 특정 버전 설치
pip install --upgrade pandas# 업그레이드
pip list                    # 설치된 패키지 목록
pip uninstall pandas        # 삭제
```
- 설치 후에는 코드에서 `import pandas as pd`로 사용.
- 설치(다운로드) → import(코드에서 불러오기)는 **다른 단계**임을 강조.

> ⚠️ 참고: 아나콘다를 쓰면 `conda install`로도 설치할 수 있다(다음 강의). 같은 패키지를 pip·conda 섞어 쓰면 충돌이 생길 수 있어 한 환경에선 한 방식을 권장.

**3줄 요약**
1. PyPI = 파이썬 패키지 창고, pip = 설치 도구.
2. `pip install 패키지`로 설치, `import`로 사용(다른 단계).
3. 판다스도 `pip install pandas`로 설치하는 외부 라이브러리.

## 6. 마무리 → 다음 강의
- 정리: 모듈(파일) → 패키지(폴더) → 라이브러리(묶음). `import`로 가져오고, 없으면 `pip install`로 설치.
