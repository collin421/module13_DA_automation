18-1

상속 — 기능 물려받기

한 클래스(자식)가 다른 클래스(부모)의 속성·메서드를 물려받음. 공통 기능을 부모에 한 번 정의하고 자식은 추가·변경만 함. class 자식(부모):, super()로 부모 호출.

📌 참고  입문 단계엔 "이런 게 있다"로 충분 — 실무에선 계층이 깊어지면 복잡해져 꼭 필요할 때만 씀. 핵심은 "공통 기능을 부모에 모아 물려받는다", "super()로 부모를 호출한다".
3줄 요약
  1. 상속은 부모의 속성·메서드를 물려받는 것.
  2. class 자식(부모):, super().__init__().
  3. 공통 기능은 부모에 모아 중복을 없앰.
인터랙티브 · 부모 → 자식

자식을 골라, 부모의 기능을 물려받고 자기만의 것을 더하는 걸 봄.

18-2

특별 메서드 — __str__

이름 앞뒤 밑줄 두 개(__)가 붙은 특별 메서드는 파이썬이 특정 상황에 자동 호출함. __str__를 정의하면 print(객체) 시 자동 호출되어 객체를 보기 좋게 표현함.

📌 참고  print(니트) → 파이썬이 니트.__str__()를 자동 호출. 던더(dunder, __)는 파이썬 특별 취급 표시. __str__만 정의해도 디버깅·리포트가 편해져 클래스 만들 때 거의 항상 추가.
3줄 요약
  1. 특별 메서드(__이름__)는 특정 상황에 자동 호출.
  2. __str__는 print(객체) 시 자동 호출.
  3. 정의하면 객체 출력이 보기 좋아짐.
인터랙티브 · print(객체)

__str__ 정의 여부를 토글해, print 결과가 어떻게 달라지는지 봄.

18-3

최종 프로젝트 ① — Product

상품 하나를 표현하는 Product 클래스에 — 속성·메서드·판정(조건문)·예외(raise)·출력(__str__) — 을 종합. 한 개념의 데이터와 동작이 한 몸이 됨.

📌 참고  raise는 예외를 직접 발생시킴(Part 16에선 잡기만). "재고보다 많이 팔려 하면 오류를 내라"를 코드로 명시 → 호출 쪽에서 try-except로 받음. 조용히 틀린 값이 흐르는 걸 막음.
3줄 요약
  1. Product에 속성·메서드·판정·예외·출력 종합.
  2. raise로 잘못된 상황에 직접 예외 발생.
  3. 한 개념의 데이터와 동작이 한 클래스에.
인터랙티브 · Product가 스스로 동작

메서드를 호출해, Product가 자기 속성으로 동작·판정·예외를 처리하는 걸 봄.

18-4

최종 프로젝트 ② — Cart

여러 Product를 품는 Cart(장바구니). 내부에 객체 리스트를 갖고, 담기·총액·요약을 함 — 객체가 다른 객체들을 품는 합성 구조. 객체들이 메서드로 협력함.

📌 참고  Cart는 Product를 상속이 아니라 포함(합성) — "장바구니는 상품이다"가 아니라 "장바구니는 상품들을 가진다". 현실의 "~을 가진다" 관계는 대부분 합성. 반복·컴프리헨션·예외·튜플이 클래스 안에 녹아듦.
3줄 요약
  1. Cart는 Product 객체들의 리스트를 품음(합성).
  2. 객체들이 메서드로 협력해 시스템을 이룸.
  3. 반복·컴프리헨션·예외·튜플이 클래스에 녹아듦.
인터랙티브 · 장바구니에 담기

상품을 눌러 담아 봄. 재고가 부족하면 예외로 담기 실패하는 걸 봄.
