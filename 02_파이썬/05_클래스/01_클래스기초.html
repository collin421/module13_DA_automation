클래스 기초

데이터(속성)와 그것을 다루는 함수(메서드)를 하나의 틀로 묶는 객체 지향의 기초. "상품 딕셔너리 + 할인가 함수"가 따로 놀던 것을, 상품이라는 하나의 설계도로 묶어 "상품이 스스로 할인가를 계산"하게 만듦.

17-1

클래스와 인스턴스 — 설계도와 실물

클래스는 설계도, 인스턴스는 그 설계도로 찍어 낸 실물(객체). class로 정의, 클래스명()으로 인스턴스 생성. 붕어빵 틀 하나로 붕어빵 여러 개를 굽는 것.

📌 참고  인스턴스는 메모리에 생성된 객체, 변수는 그것을 가리킴(Part 1). 지금까지 다룬 값(숫자·리스트·딕셔너리)이 다 객체였고, 클래스는 내가 직접 새 종류의 객체를 정의하는 것. 클래스 이름은 대문자 시작 관례.
3줄 요약
  1. 클래스는 설계도, 인스턴스는 그 설계도로 찍은 실물.
  2. class 이름:으로 정의, 이름()으로 생성.
  3. 인스턴스는 메모리에 생성된 객체, 변수는 그것을 가리킴.
인터랙티브 · 틀로 실물 찍어 내기

17-2

__init__과 속성 — 데이터 담기

__init__는 인스턴스 생성 시 자동 실행되어 속성을 붙임. self는 지금 만들어지는 그 인스턴스 자신. self.이름 = 이름은 "이 객체의 이름 속성에 값을 담아라".

📌 참고  __init__의 첫 매개변수는 항상 self. 호출 시 self는 직접 안 넘김 — 상품("니트", 89000, 12)처럼 나머지만 넘기면 파이썬이 새 객체를 self로 자동으로 채워 줌. 속성은 객체.속성으로 접근(딕셔너리의 ["키"]와 비슷).
3줄 요약
  1. __init__는 생성 시 자동 실행되어 속성을 붙임.
  2. self는 지금 다뤄지는 그 인스턴스 자신.
  3. 속성은 self.속성 = 값으로 담고 객체.속성으로 꺼냄.
인터랙티브 · 객체 만들기

값을 넣고 "생성"하면, __init__가 그 값들을 객체의 속성으로 담는 걸 봄.

17-3

메서드 — 객체가 하는 일

메서드는 클래스 안의 함수로, self로 자기 속성을 이용해 동작함. "상품이 자기 할인가를 계산", "재고를 줄임" — 데이터(속성)와 동작(메서드)이 한 몸이 됨.

📌 참고  니트.할인가()는 할인가(self=니트)로 실행 — 점 앞의 객체가 자동으로 self. 메서드 안에서 자기 속성은 반드시 self.(self.가격) — 빼먹으면 지역 변수를 찾아 오류남. Part 12 함수는 데이터를 인자로 받았지만, 메서드는 데이터를 자기 안에 가짐.
3줄 요약
  1. 메서드는 클래스 안 함수, 객체의 속성을 이용해 동작.
  2. 첫 매개변수 self로 자기 속성에 접근·변경.
  3. 데이터(속성)와 동작(메서드)이 한 몸이 되는 게 핵심.
인터랙티브 · 객체가 스스로 동작

메서드를 호출해, 객체가 자기 속성(self.가격·self.재고)으로 동작하는 걸 봄.

17-4

딕셔너리 vs 클래스

"상품 하나"를 딕셔너리로도 클래스로도 표현 가능. 단순하면 딕셔너리, 동작이 많고 여러 개 다루면 클래스. 포스트잇 메모 vs 정식 서식 양식.

📌 참고  "딕셔너리로 충분하면 딕셔너리, 동작이 많아지면 클래스". 데이터 분석 중간 데이터는 딕셔너리·리스트, 클래스는 "장바구니 시스템"·"게임 캐릭터"처럼 상태와 동작이 많은 걸 모델링할 때 빛남. 둘 다 도구.
3줄 요약
  1. 딕셔너리는 데이터+따로 함수, 클래스는 데이터+동작 한 몸.
  2. 접근이 ["키"](딕트) vs .속성(클래스).
  3. 단순하면 딕셔너리, 동작 많고 여러 개면 클래스.
인터랙티브 · 같은 데이터, 다른 표현

표현 방식을 골라, 데이터 접근과 동작이 어떻게 다른지 비교.

17-5

여러 인스턴스 — 독립된 객체들

같은 클래스로 인스턴스를 여러 개 만들면 각자 독립된 속성을 가짐 — 하나를 바꿔도 다른 것엔 영향 없음. 인스턴스들을 리스트에 담아 반복하면 자료구조·반복·메서드가 모두 결합됨.

📌 참고  "딕셔너리들의 리스트"(Part 7)가 "객체들의 리스트"로 발전한 셈 — 각 원소가 자기 동작(메서드)을 가진 객체. for s in 상품들: s.할인가()처럼 반복하며 메서드를 호출하는 게 객체 지향의 흔한 패턴.
3줄 요약
  1. 같은 클래스로 만든 인스턴스들은 각자 독립된 속성.
  2. 한 객체의 속성을 바꿔도 다른 객체엔 영향 없음.
  3. 인스턴스들을 리스트에 담아 반복하며 메서드를 호출.
인터랙티브 · 독립성 확인

"니트만 판매"를 눌러, 니트 재고만 줄고 코트는 그대로인 독립성을 봄.
