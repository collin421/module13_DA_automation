파이썬 기초 문법 · Part 16 · 실전과 클래스

모듈·예외·파일

프로그램을 실전 수준으로 — 코드 가져다 쓰기(모듈), 오류에 안전하게 대응(예외), 데이터를 디스크에 영구 저장(파일). 특히 파일은 Part 1의 "값은 메모리라 끝나면 사라진다 → 영구 저장은 파일"의 바로 그 파일.

🔴 실전 · 16/18 import · try-except · file 예상 40분
16-1

모듈 — 코드 가져다 쓰기

import로 함수·기능이 모인 코드 묶음 파일을 가져와 씀. 망치를 직접 만들 필요 없이 도구 상자를 가져오는 것 — Part 0의 "거인의 어깨".

📌 참고  자주 쓰는 표준 모듈 — math·random·statistics·datetime·os. pandas·numpy는 외부 모듈(다음 단계)이고 import pandas as pd처럼 별명을 붙이는 게 분석 관례.
3줄 요약
  1. 모듈은 코드 묶음 파일, import로 가져와 씀.
  2. import 모듈 / from ... import / as 별명.
  3. 표준·외부 라이브러리로 기능을 재사용함.
인터랙티브 · 세 가지 import 방식

방식을 골라, 같은 기능을 가져오는 세 문법을 비교(결과는 같음).

16-2

예외 — 오류에 안전하게

실행 중 오류(예외)가 나면 프로그램이 그 자리에서 죽음. try-except로 예외를 "잡아" 죽지 않고 대응함 — 안전망. try 중 예외가 나면 즉시 except로 점프.

📌 참고  자주 만나는 예외 — ValueError·ZeroDivisionError·KeyError·IndexError·FileNotFoundError. 데이터 1000개 중 1개가 잘못돼도 전체가 안 멈추게! 단, 예상되는 오류만 콕 집어 잡을 것(넓은 except는 진짜 버그를 숨김).
3줄 요약
  1. 예외는 실행 중 오류, 나면 프로그램이 멈춤.
  2. try-except로 예외를 잡아 죽지 않고 대응.
  3. 예상되는 오류만 구체적으로 잡는 게 좋음.
인터랙티브 · try → except 흐름

입력값을 골라, 예외가 날 때 코드가 어디로 점프하는지 봄.

16-3

파일 쓰기 — 메모리 → 디스크 ⭐

지금까지 값은 메모리(RAM)에 있어 프로그램이 끝나면 사라졌음(Part 1). 영구히 남기려면 파일(디스크)에 써야 함. 화이트보드(메모리)에서 노트(파일)로 옮겨 적는 것.

⚠️ 참고  모드 "w"는 기존 파일을 덮어씀(이어쓰기는 "a"). 항상 with open(...) as f: 형태를 쓰면 파일이 자동으로 닫혀 안전. encoding="utf-8"로 한글 깨짐 방지. 이제 Part 1의 "메모리 vs 디스크"가 완성됨.
3줄 요약
  1. 메모리의 값은 종료 시 사라지므로 파일에 저장함.
  2. with open(파일,"w",encoding="utf-8") as f: f.write(...).
  3. with가 파일을 자동으로 닫아 안전, "w"는 덮어씀.
인터랙티브 · 종료 시 메모리는 사라지고 파일은 남는다

"파일에 쓰기" 후 "프로그램 종료"를 눌러, 메모리 값은 사라져도 파일은 남는 걸 봄.

16-4

파일 읽기 — 디스크 → 메모리

저장한 파일을 다시 읽어 들여 프로그램에서 씀. "r" 모드로 열고, for 줄 in f:로 한 줄씩 순회(파일도 iterable — Part 10). 없는 파일은 FileNotFoundError.

📌 참고  파일 읽기는 반복(Part 10)·문자열(Part 4)·예외(16-2)가 한데 모이는 지점 — for 줄 in f로 순회하고 .strip()·.split(",")로 가공하고 try-except로 없는 파일에 대비.
3줄 요약
  1. "r" 모드로 읽음(read/readlines).
  2. for 줄 in f:로 한 줄씩 순회(파일도 iterable).
  3. 없는 파일은 FileNotFoundError, try-except로 대비.

16-5

종합 — CSV 저장·불러오기

데이터 분석의 표준 형식 CSV(쉼표로 구분된 표)를 다룸. "딕셔너리들의 리스트"를 CSV로 저장하고 다시 읽어 복원 — 반복·문자열·형변환·딕셔너리·파일이 모두 결합됨.

📌 참고  CSV 값은 모두 문자열로 읽힘 → 숫자는 int()·float() 형변환 필요(Part 1·3의 input과 같은 원리). 실무에선 import csv나 pandas.read_csv()가 자동 처리하지만, 그 밑단 동작이 바로 이것.
3줄 요약
  1. CSV는 쉼표로 구분된 표 데이터의 표준 형식.
  2. 딕셔너리 리스트를 CSV로 쓰고 읽어서 복원함.
  3. 읽은 값은 문자열이라 숫자는 형변환이 필요함.
인터랙티브 · 저장 → 파일 → 복원 사이클

단계를 따라가며, 딕셔너리 리스트가 CSV로 저장되고 다시 복원되는 걸 봄.
