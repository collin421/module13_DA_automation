문자열 다루기

이미 만난 문자열을 깊이 다룸. 글자를 하나씩 꺼내고(인덱싱), 잘라 내고(슬라이싱), 메서드로 가공함. 그리고 "한 번 만들면 못 바꾼다"는 동작 원리 불변성도 익힘 — 지저분한 데이터를 정리하는 데이터 전처리의 첫걸음.

🟡 자료구조 · 4/18 인덱싱 · 슬라이싱 · 메서드 예상 35분
4-1

인덱싱 — 글자를 하나씩

문자열은 글자가 순서대로 늘어선 묶음. 각 글자엔 자리 번호(인덱스)가 있어 [번호]로 꺼냄. 번호는 0부터, 음수는 뒤에서부터(-1이 맨 끝)임.

📌 참고  "0부터 센다"가 입문자가 가장 헷갈리는 지점. 첫 글자 = [0], 마지막 글자 = [-1] 또는 [len()-1]. 없는 자리([5])를 꺼내면 오류가 남.
3줄 요약
  1. 각 글자는 [번호]로 꺼냄 — 번호는 0부터.
  2. 음수 인덱스는 뒤에서부터, -1이 맨 마지막.
  3. len()으로 글자 수를 세고 마지막 인덱스는 len()-1.

4-2

슬라이싱 — 잘라 내기

[시작:끝]으로 여러 글자를 한 번에 자름. 시작은 포함, 끝은 불포함 — 그래서 [0:3]은 3개. 칼이 끝 번호 앞에서 멈춘다고 생각하면 쉬움.

📌 참고  [::-1](거꾸로 뒤집기)은 자주 쓰는 관용구. 슬라이싱은 범위를 벗어나도 오류 없이 빈 문자열을 돌려줌(인덱싱이 오류 나는 것과 다름). 날짜 "2025-01-15"에서 [:4]로 연도를 뽑는 식으로 씀.
3줄 요약
  1. 슬라이싱 [시작:끝]으로 여러 글자를 자름.
  2. 시작 포함, 끝 불포함 — [0:3]은 3개.
  3. [::-1]은 거꾸로, 빈 칸은 처음/끝/전체.

4-3

변형 메서드와 불변성 ⭐

문자열.기능()으로 가공함(upper·strip·replace 등). 핵심 동작 원리 — 문자열은 불변(immutable)이라 메서드는 원본을 안 바꾸고 새 문자열을 만들어 돌려줌. 쓰려면 다시 담아야 함(Part 1 바인딩).

📌 참고  왜 불변일까? 값이 안 바뀌도록 보장하면 코드가 안전·예측 가능해짐(다른 곳에서 쓰던 문자열이 나도 모르게 바뀌는 사고 방지). 숫자·불리언도 불변. 반대로 다음 파트의 리스트는 가변이라 동작이 다름.
3줄 요약
  1. 메서드는 문자열.기능()으로 부름.
  2. 문자열은 불변 — 메서드는 새 문자열을 돌려줌.
  3. 결과를 쓰려면 다시 변수에 담아야(재할당) 함.
인터랙티브 · 원본은 안 바뀐다

메서드를 적용해 봄. 원본은 그대로 남고, "다시 담기"를 눌러야 변수가 새 값을 가리킴.

4-4

검색과 포함 — 찾고 확인하기

in(포함 여부, 참/거짓)·.find()(위치, 없으면 -1)·.count()(횟수). in은 결과가 불리언이라 필터·조건에 바로 쓰임.

📌 참고  단순히 "들어 있나"만 알고 싶으면 in이 가장 읽기 쉽고 파이썬다움. 데이터 필터에 자주 씀 — "상품명에 '세일'이 들어간 것만", "이메일에 '@'가 있는지" 등.
3줄 요약
  1. in으로 포함 여부(참/거짓)를 가장 간단히 확인.
  2. .find()는 위치를 돌려주고 없으면 -1.
  3. in은 필터·조건의 단골 도구임.

4-5

분리와 결합 — split과 join

.split(구분자)로 쪼개 리스트로 만들고, "연결자".join(리스트)로 이어 문자열로 만듦. 콤마로 묶인 데이터(CSV)를 다루는 전처리의 핵심 — 자르고(split) 붙이는(join) 짝임.

📌 참고  .split()의 결과는 리스트임 — 그래서 다음 파트(리스트)가 바로 이어짐. CSV를 다룰 때 .split(",")가 가장 기초적인 도구이고, 나중엔 pandas가 이를 자동화함.
3줄 요약
  1. .split(구분자)로 잘라 리스트로 만듦.
  2. "연결자".join(리스트)로 이어 문자열로 만듦.
  3. 자르고 붙이는 split↔join이 데이터 정리의 기본 패턴.
