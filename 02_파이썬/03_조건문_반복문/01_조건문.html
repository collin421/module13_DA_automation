조건문

상황에 따라 다르게 행동하는 법. "재고 있으면 판매, 없으면 품절"처럼, Part 2의 참/거짓이 드디어 판단에 따른 분기로 이어짐. 파이썬의 특징인 들여쓰기로 코드 묶음을 구분하는 원리도 익힘.

🟠 흐름 제어 · 9/18 if · elif · else 예상 35분
9-1

if — 참일 때만 실행

if 조건:은 조건이 참일 때만 딸린 코드를 실행함. if 뒤엔 콜론 :, 다음 줄은 들여쓰기(공백 4칸). 파이썬은 들여쓰기로 코드 묶음을 구분함.

📌 참고  들여쓰기는 보통 공백 4칸으로 통일(편집기가 자동). 탭과 공백을 섞으면 오류. "콜론 다음 줄은 들여쓴다"가 조건문·반복문·함수 모두 같은 규칙임.
3줄 요약
  1. if 조건:은 조건이 참일 때만 딸린 코드 실행.
  2. if 뒤 콜론 :, 다음 줄은 들여쓰기.
  3. 파이썬은 들여쓰기로 코드 묶음을 구분함.
인터랙티브 · 조건에 따라 실행/건너뜀

재고를 슬라이더로 바꿔, 들여쓴 코드가 실행되는지(초록) 건너뛰는지(흐림) 봄.

재고 = 12
9-2

if-else — 두 갈래

조건이 참이면 if, 거짓이면 else. 둘 중 정확히 하나만 실행됨. else엔 조건을 적지 않음(나머지 전부).

📌 참고  두 갈래 판단(있다/없다, 통과/탈락)에 딱 맞음. "조건에 따라 값을 다르게 정하기"(등급·상태·라벨)가 대표 쓰임. 세 갈래 이상은 elif.
3줄 요약
  1. else는 조건이 거짓일 때 실행할 코드.
  2. if-else는 둘 중 정확히 하나만 실행.
  3. else엔 조건을 적지 않음(나머지 전부).
인터랙티브 · 갈림길

재고를 바꿔, if와 else 중 어느 길로 가는지 봄.

재고 = 0
9-3

elif — 여러 갈래 (검문소)

elif로 세 갈래 이상. 위에서부터 차례로 검사해 처음 참인 곳에서 멈춰 그 코드만 실행하고 나머지는 건너뜀 — 그래서 순서가 중요함.

📌 참고  "처음 맞는 하나만 실행"이라 조건이 겹쳐도 위쪽 우선 — 보통 엄격한(높은) 기준부터 배치함. 순서를 거꾸로 두면 85가 >=70에 먼저 걸려 엉뚱해짐.
3줄 요약
  1. elif로 세 갈래 이상의 조건을 이어 붙임.
  2. 위에서부터 검사해 처음 참인 하나만 실행.
  3. 조건 순서가 중요함(보통 엄격한 것부터).
인터랙티브 · 점수 → 학점 검문소

점수를 바꿔, 위에서부터 검사하다 처음 통과하는 조건(초록)을 봄.

점수 = 85
9-4

조건 안의 논리

조건에 and·or·not(Part 2)을 써 여러 조건을 묶음. 여러 자물쇠가 걸린 문처럼 — and는 모두 풀려야, or는 하나만 풀려도 열림.

📌 참고  간단한 결합은 and/or로(권장), 단계별 안내가 필요할 때만 중첩. 복잡한 조건은 변수에 담으면(프리미엄 = 가격>=100000) if 프리미엄:처럼 읽기 쉬워짐.
3줄 요약
  1. 조건에 and·or·not으로 여러 조건을 묶음.
  2. if 안에 if 중첩도 가능함.
  3. 간단한 결합은 논리로, 단계별 안내는 중첩으로.
인터랙티브 · 무료 배송 조건

회원 여부와 구매액을 바꿔, 회원 and 구매액>=50000 조건의 결과를 봄.

회원
구매액 = 60000
9-5

실전 — 딕셔너리 판정기

Part 7의 딕셔너리에서 값을 꺼내 조건문으로 판정함 — "데이터 한 건을 규칙에 따라 처리"하는 기본 형태. 상품의 재고 상태와 가격 등급을 라벨로 붙임.

📌 참고  지금은 상품 한 개를 판정했음. 1000개라면 이 판정을 1000번? → 반복문(Part 10)이 필요. 조건문(판단) + 반복문(되풀이) = "모든 건에 판단 적용" = 진짜 자동화.
3줄 요약
  1. 딕셔너리에서 값을 꺼내 조건문으로 한 건을 판정.
  2. if-elif-else로 상태·등급 라벨을 붙임.
  3. 한 건 처리 규칙 + 반복문 = 전체 자동화.
인터랙티브 · 상품 판정기

상품을 골라, 조건문이 재고 상태와 가격 등급을 어떻게 판정하는지 봄.
